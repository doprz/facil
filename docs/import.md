# Importing from tmuxinator

`facil import <path> [name]` converts a tmuxinator YAML config into a facil
TOML config. `<path>` is the tmuxinator file to read - it isn't resolved
through facil's own [config discovery](config.md#file-discovery), it's just an
input file. `[name]` is optional: given, the result is written to
`~/.config/facil/<name>.toml`; omitted, the name comes from the YAML's own
top-level `name:` field. Either way, the same no-clobber rule as `new`/`copy`/
`snapshot` applies - it's an error if the destination already exists.

This is a **best-effort, review-before-use** conversion, not a guarantee of
byte-for-byte equivalent behavior. It hard-errors only when the file can't be
meaningfully converted at all; everywhere else, an unrecognized or unsupported
shape is imported as best it can and noted as a warning rather than failing
the whole import - partial success beats none. Every warning is both printed
after the import and written as a `#` comment block at the top of the
generated file, so nothing is silently dropped.

## Field mapping

| tmuxinator | facil | Notes |
|---|---|---|
| `name` | `name` | direct |
| `root` (or the older `project_root`) | `root` | direct |
| `socket_name` | `socket_name` | direct |
| `tmux_options` | `tmux_options` | direct |
| `pre` (string or array) | `pre` | normalized to an array. **Timing differs**: facil's `pre` runs after the tmux session is created (see the [build order](config.md#build-order)); tmuxinator's runs before any tmux state exists. Always flagged as a warning when `pre` is non-empty. |
| `post` (string or array) | `post` | normalized to an array; same host-level, run-after-everything semantics either way |
| top-level `pre_window` (string or array) | pushed onto every window's `pre_window` that doesn't define its own | facil has no session-wide `pre_window` field - a window-level `pre_window` (or the older `pre` key on a window) in the source YAML still wins, matching tmuxinator's own precedence |
| `windows[].<name>.layout` | `windows[].layout` | direct |
| `windows[].<name>.pre_window` / `.pre` (window-level) | `windows[].pre_window` | normalized to an array |
| `windows[].<name>.root` | `windows[].root` | direct - facil has a real window-level `root` |
| `windows[].<name>.panes[]` - string, list of strings, or blank | `windows[].panes[].commands` | normalized to an array; blank/null → `[]` |
| `windows[].<name>` as a bare string (no `panes` key) | one window, one pane, `commands: [that string]` | tmuxinator's shorthand form |
| `project_hooks.on_project_start` | appended to `pre` | best-effort - closest lifecycle match, flagged as a warning |
| `project_hooks.on_project_exit` / `on_project_stop` | appended to `post` | same |
| `project_hooks.on_project_first_start` / `on_project_restart` | - | no facil equivalent; skipped, flagged as a warning |
| `startup_window` (name or index) | `attach_window` | direct when given as a name. When given as a tmux window **index**, it's carried over as facil's 1-based window-list position instead - these can differ if tmuxinator's index depends on a non-default `base-index`, so this case gets a warning to double-check it still points at the right window. |
| `attach`, `startup_pane`, pane-title/display options, and any other unrecognized key | - | not imported; every unrecognized top-level or window-level key produces a warning |

A pane entry that's a YAML mapping (an advanced/uncommon shape in older
tmuxinator configs) isn't understood - it's imported as a single empty pane
with a warning rather than causing the whole import to fail.

## Worked example

Input (`sample.yml`):

```yaml
name: sample
root: ~/code/sample
pre: docker compose pull
pre_window: rbenv shell 2.0.0-p247
startup_window: logs

windows:
  - editor:
      layout: main-vertical
      panes:
        - vim
        - guard
  - server: bundle exec rails s
  - logs:
      root: ~/code/sample/logs
      panes:
        - tail -f dev.log
```

`facil import sample.yml` produces:

```toml
# generated by `facil import` - review before use
# - facil's `pre` runs after the tmux session is created; tmuxinator's `pre` runs before any tmux state exists - review timing-sensitive commands

name = "sample"
root = "~/code/sample"
pre = ["docker compose pull"]
attach_window = "logs"

[[windows]]
name = "editor"
layout = "main-vertical"
pre_window = ["rbenv shell 2.0.0-p247"]

[[windows.panes]]
commands = ["vim"]

[[windows.panes]]
commands = ["guard"]

[[windows]]
name = "server"
pre_window = ["rbenv shell 2.0.0-p247"]

[[windows.panes]]
commands = ["bundle exec rails s"]

[[windows]]
name = "logs"
root = "~/code/sample/logs"
pre_window = ["rbenv shell 2.0.0-p247"]

[[windows.panes]]
commands = ["tail -f dev.log"]
```

Note the top-level `pre_window` was copied onto all three windows (none of
them defined their own), `logs`' window-level `root` mapped straight across,
and `startup_window: logs` became `attach_window = "logs"` with no caveat
needed since it was given as a name, not an index. Run `facil validate` (or
just open the file, since `import` opens `$EDITOR` automatically) before
starting it for the first time.
